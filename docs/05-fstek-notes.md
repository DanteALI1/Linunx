# Ориентиры ФСТЭК для контура РЕД ОС 8

Документ **не заменяет** формальные требования сертификации и модели угроз организации.
Фиксирует, как данная схема RBAC соотносится с типовыми ожиданиями по СЗИ.

## Соответствие практикам

| Ожидание (ориентир) | Реализация в комплекте |
|---------------------|------------------------|
| Разграничение полномочий администраторов | Роли svcsec / svcsecadmin / poinstall / editor / timeditor |
| Минимизация привилегий | sudoers whitelist, sudoedit, NOEXEC, без root-shell у editor |
| Мандатный контроль | SELinux enforcing |
| Регистрация событий ИБ | auditd rules + sudo I/O log + ключи ausearch |
| Контроль целостности ПО | SHA256 approve staging→approved; опц. подпись пакетов |
| Защита средств администрирования | SSH deny svcsecadmin; запись sudoers/PAM/SSH только admin |
| Контроль запуска ПО | SELinux + опц. fapolicyd; noexec на data |
| Управление конфигурацией | Изменения conf — sudoedit + audit `wazuh_conf` |
| Временные привилегии | timeditor TTL 8ч + audit `timeditor_expire` |

## Рекомендуемые орг. меры

1. Назначить владельца роли svcsecadmin (персональная ответственность).
2. Хранить артефакты и checksums во внешнем реестре поставок.
3. Периодический разбор `ausearch` / SIEM (в т.ч. Wazuh Manager как приёмник).
4. Запрет совместного использования УЗ; ключи SSH на смарт-картах/НЖМД по политике.
5. Регламент rollback и аварийного доступа к консоли.

## Что не заявлено как «сертификация из коробки»

- Готовый профиль сертификации ФСТЭК на данный git-комплект.
- Автоматическое закрытие всех требований конкретного ТЗ/Классов СВТ.

Используйте как **технический каркас** внедрения на РЕД ОС 8 в рамках принятой модели угроз.
